# Железо

Данные по T-Dongle-S3 — из официального репозитория
[Xinyuan-LilyGO/T-Dongle-S3](https://github.com/Xinyuan-LilyGO/T-Dongle-S3),
`docs/en/t-dongle-s3*/REAMDE.MD` и `examples/lcd/lcd.ino`.

## Выбранные платы

| Роль | Плата | Обоснование |
|---|---|---|
| **RX — донгл** | LilyGo **T-Dongle-S3-Plus** | форм-фактор USB-флешки: втыкается прямо в порт хоста, питается от шины; дисплей для человека; слот TF |
| **TX — передатчик** | ESP32-S3 **Supermini** | минимальный размер, крепится у руля |

## Платы на руках: замерено, а не по коробке

Обе опрошены `esptool` 01.08.2026. Это **не** стоковые DevKitC-1 (у тех
мост CP2102N) — два разных клона, но кремний одинаковый:

| | Плата A | Плата B |
|---|---|---|
| Чип | ESP32-S3 QFN56 rev v0.2 | то же |
| Флеш | **16 МБ** (boya, 0x684018) | то же |
| PSRAM | **8 МБ, встроенная (AP_3v3)** | то же |
| Мост USB-UART | FTDI FT232R (`0403:6001`) | WCH CH343 (`1A86:55D3`) |
| Порт на маке | `/dev/cu.usbserial-A5069RR4` | `/dev/cu.usbmodem5B5E0652411` |
| **MAC** | `ac:a7:04:ee:5f:d0` | `ac:a7:04:12:68:50` |

MAC-адреса понадобятся в M3: пиринг ESP-NOW идёт по ним.

### Цвет индикатора: чем платы различаются на столе

Платы одинаковые, и понять, какая перед тобой, иначе нельзя — только по
цвету. Рабочее состояние окрашено ролью:

| Роль | Рабочее состояние | Ищет собеседника | Авария |
|---|---|---|---|
| **TX** | зелёный | жёлтый | красный |
| **RX** | **голубой** | жёлтый | красный |

Голубой, а не синий: синий уже занят состоянием «поднимаюсь», и различать
их по оттенку одного цвета на глаз никто не станет.

**Жёлтый и красный роли не знают, и это не забывчивость.** Красный значит
«сломалось» и обязан читаться одинаково на любой плате; жёлтый — «ищу
собеседника» или «жду хоста». Если TX мигает жёлтым — он не нашёл RX, и
самая частая причина этого не поломка, а то, что RX залит прошивкой M2
(`rx-gip`), в которой радиолинка нет вовсе.

**Роли назначены 02.08.2026: плата A — TX, плата B — RX.** Менять без нужды
не стоит: адрес пира лежит в NVS каждой платы, и после перестановки ролей
обе полезут искать друг друга заново. Прошивать по портам явно:

```
pio run -d firmware/tx -e tx-devkit -t upload --upload-port /dev/cu.usbserial-A5069RR4
pio run -d firmware/rx -e rx-devkit -t upload --upload-port /dev/cu.usbmodem5B5E0652411
```

### Два следствия

**Это N16R8 — та же память, что у целевого T-Dongle-S3-Plus.** Открытый
вопрос «взят ли вариант Plus» касается только донгла; на разработке PSRAM
уже есть. Значит кольцевой журнал трасс для M2 можно делать сразу, не
дожидаясь донгла, и упиравшаяся в него задача перестаёт быть отложенной.

**Мосты разные, значит платы разной разводки.** Пин светодиода на одной
может не совпадать с другой — проверять надо каждую отдельно.

## Профили сборки

Целевые платы ещё не пришли, разработка идёт на девкитах. Профили обеих
плат живут в `platformio.ini` каждой прошивки, переключаются одним `-e`:

```
pio run -d firmware/tx                  # tx-devkit, плата на руках
pio run -d firmware/tx -e tx-supermini  # целевая
pio run -d firmware/rx                  # rx-devkit
pio run -d firmware/rx -e rx-dongle     # целевая
```

Что теряется на девките и что выигрывается:

| | T-Dongle / Supermini | DevKitC-1 |
|---|---|---|
| Отладочный лог | QWIIC → внешний USB-UART | **второй порт платы**, мост UART |
| Индикатор | APA102 / одиночный светодиод | адресный WS2812 |
| Дисплей 160×80 | есть на RX | нет, статус в UART |
| Слот TF | есть на RX | нет, трассы M2 в UART |
| Форм-фактор | флешка в порт хоста | на проводе |

Отладка на девките **проще**: нативный USB занят ролью, но второй порт
свободен и `pio device monitor` работает как обычно. Переходник QWIIC не
нужен, пока не появится T-Dongle.

Потери реальны только на M2: эталоны с шести платформ придётся гнать в UART
на 115200 вместо записи на карту. На состав эталонов это не влияет, только
на скорость снятия.

## Распайка USB: три провода

У ESP32-S3 один USB-OTG контроллер со встроенным PHY, и он прибит к
конкретным ногам. Перенести нельзя — это кремний, а не мультиплексор.

| Сигнал | GPIO |
|---|---|
| USB **D−** | **19** |
| USB **D+** | **20** |
| GND | любая земля платы |

VBUS (+5 В) — не вывод контроллера, это питание, и разводится отдельно.

### RX → хост (роль device)

У DevKitC-1 нативный USB уже разведён на разъём с подписью `USB` (не
`UART`). Паять нечего: кабель USB-A ↔ разъём платы, и донгл воткнут в
консоль или ПК.

Если нативного разъёма на плате нет — папа USB-A на провода:

| Провод | Куда |
|---|---|
| D− | GPIO19 |
| D+ | GPIO20 |
| GND | GND |
| +5 В | пин `5V` платы |

Хост питает донгл по шине — как и задумано. Цвета проводов в кабелях
(белый D−, зелёный D+) — соглашение, а не гарантия: прозванивать.

### TX → руль (роль host)

**Руль вскрывать не надо.** У G920 штатный кабель USB-A; нужна USB-A
**мама**, в неё этот кабель и втыкается. Внутренней распиновки платы руля
проект не использует нигде: всё, что снимает M1 — дескрипторы, метаданные,
трафик, переключение в `c262` — идёт по штатному кабелю.

| Контакт USB-A мамы | Куда |
|---|---|
| 1 (+5 В) | **внешние 5 В** |
| 2 (D−) | GPIO19 |
| 3 (D+) | GPIO20 |
| 4 (GND) | GND платы **и** минус внешних 5 В |

Ключевое: **VBUS подаёт передатчик**. Руль питается от своего 24 В БП, но
его USB-интерфейс не начнёт энумерацию, пока не увидит 5 В на VBUS — он
ждёт, что в него воткнули хост.

Пин `5V` платы для этого брать не стоит: на девките он висит на шине
питания через диод Шоттки, и подача туда обратно кормит регулятор платы с
выхода. Нужен отдельный источник — повербанк, зарядка, лабораторник.

Земля общая: плата, внешние 5 В, розетка. Иначе у D+/D− нет опоры и
энумерация не пойдёт.

### Одна плата — одна роль

У S3 один USB-OTG контроллер: либо Host, либо Device, переключение на лету
невозможно. Отсюда две прошивки и **две платы** — это не удобство сборки, а
ограничение кремния.

## ✅ Блокирующий вопрос снят: USB заведён на нативный OTG

Документация прямо описывает переключение `USB Mode` между
`Hardware CDC and JTAG` и **`USB-OTG (TinyUSB)`**, а плата заявлена как
«native USB — no driver, no serial chip».

**Значит USB-A разъём донгла посажен на нативный USB-OTG контроллер, и роль
USB Device со своими дескрипторами реализуема.** Плата для RX годится.

Побочное следствие для разработки: как только прошивка переключит режим в
USB-OTG, автоматическая заливка перестанет работать. Дальше — только вручную:
зажать BOOT, воткнуть в порт, залить. Это надо заложить в рабочий цикл с
самого начала, иначе будет неприятным сюрпризом на первой же прошивке M2.

## ⚠️ Берите именно Plus: у обычного нет PSRAM

| Вариант | Flash | SRAM | PSRAM |
|---|---|---|---|
| T-Dongle-S3 | 16 МБ | 512 КБ | **нет** |
| **T-Dongle-S3-Plus** | 16 МБ | 512 КБ | **8 МБ (OPI)** |
| T-Dongle-S3-Dual | 16 МБ ×2 | 512 КБ ×2 | нет |

Обозначение **N16R8 соответствует варианту Plus**. У обычного T-Dongle-S3
PSRAM отсутствует.

Строго говоря, задача влезает и в 512 КБ: кэш личности руля — единицы
килобайт, очереди линка — тоже. Но PSRAM даёт запас под кольцевой журнал
трафика, а это ровно то, что нужно на этапах снятия эталонов.

Вариант **Dual** (две отдельные микросхемы S3 на одной плате) нам не нужен
и вреден: программируется через мост CH34x, то есть USB там устроен иначе.

## Распиновка T-Dongle-S3

### Дисплей — ST7735, 160×80, 0.96", SPI2_HOST

| Сигнал | GPIO |
|---|---|
| MOSI | 3 |
| CLK | 5 |
| CS | 4 |
| DC | 2 |
| RST | 1 |
| Подсветка (BL) | 38 |
| MISO | не подключён |

Подсветка активна низким уровнем (`LCD_BK_LIGHT_ON = 0`), управляется через
LEDC.

### Остальное

| Узел | GPIO |
|---|---|
| APA102 RGB LED (порядок BGR) | DIN 40, CLK 39 |
| Кнопка BOOT | 0 |
| QWIIC | TX 43, RX 44 |
| TF-карта (SDMMC) | CLK 12, CMD 16, D0 14, D1 17, D2 21, D3 18 |

Питание: 4.8–5.5 В от USB, максимальный ток 800 мА.

## Три следствия из распиновки

### 1. Отладочный UART — это QWIIC

GPIO43/44 — штатные выводы UART0. Раз USB занят ролью device, логировать в
USB-CDC нельзя, и **QWIIC-разъём становится единственным каналом отладки**.

→ Нужен переходник QWIIC → USB-UART. Заказать вместе с платой, без него
отладка RX невозможна в принципе.

### 2. Кнопка одна, и она же BOOT

GPIO0 — единственная кнопка, и она же переводит плату в режим загрузки при
удержании **в момент подачи питания**.

Отсюда жёсткое ограничение на аварийный оверрайд режима: **нажатие
засчитывается только после загрузки**, удержание при втыкании использовать
нельзя — плата уйдёт в bootloader вместо смены режима. В брифинге оверрайд
описан как «долгое удержание кнопки» — уточнение: долгое удержание
**в работе**, не при подключении.

### 3. Слот TF — это журнал трасс

Неожиданный подарок. На этапах M1–M2 нужно снимать полные дампы USB-трафика
и эталоны энумерации, и гнать их в UART на 115200 — медленно и с потерями.

**Пишем трассы на карту.** Полный лог сессии с микросекундными метками
ложится на TF без спешки, потом снимается на компьютер и разбирается
спокойно. Это заметно ускоряет M2, где эталонов надо снять с шести
платформ, причём часть — с холодного старта, когда UART-консоль ещё не
подключена.

Для TX (Supermini, слота нет) остаётся UART или пересылка трасс по ESP-NOW
на RX с записью на карту — второе после того, как заработает M3.

## Экран состояния: 160×80 — это мало

На 0.96" при читаемом шрифте помещается примерно 5–6 строк. Всё сразу не
влезет, поэтому — одна постоянная сводка и страницы по кнопке.

**Главный экран (всегда):**

```
HOST: XBOX          ← вердикт: ОПРЕДЕЛЕНИЕ / ПК / XBOX
WHEEL: c261 OK      ← руль: режим и наличие
LINK: -42 dBm       ← радио: RSSI
LAT: 2.1ms  0.1%    ← задержка и потери
AUTH: OK            ← только в Xbox-режиме
```

**Страницы по кнопке:** частота отчётов, счётчики кадров по типам, журнал
последних ошибок, версии прошивок обеих сторон.

**Аварии — во весь экран, с приоритетом над всем:**

```
!! LINK LOST !!
FORCES OFF
```

RGB-светодиод APA102 дублирует состояние цветом, чтобы понимать статус не
вглядываясь: зелёный — работает, жёлтый — определение, красный — авария.

## TX: ESP32-S3 Supermini

### ⚠️ Проверить до первого кода

- [ ] **VBUS для роли Host.** Руль питается от своего БП, но его
      USB-интерфейс всё равно ждёт 5 В на VBUS, чтобы энумерироваться.
      Supermini обязан подать питание в линию: нужен OTG-переходник и
      внешние 5 В — сам разъём платы на выдачу не рассчитан.
- [ ] **Вариант по памяти** (N4 / N8, PSRAM). Для TX хватит минимального,
      но надо знать точно.
- [ ] Свободный UART для отладки — USB занят ролью host.
- [ ] Разъём для врезки в линию руля: USB-A мама или пайка.

TX питается **не от хоста**, а от своего источника — от БП руля или
отдельного адаптера.

### Индикация TX

Дисплея нет, только светодиод. Кодировать морганием: линк есть / линка нет /
руль не подключён / сработала мёртвая рука.

## Что заказать

| Позиция | Зачем | Когда нужно |
|---|---|---|
| LilyGo **T-Dongle-S3-Plus** | RX | M0 |
| **ESP32-S3 Supermini** | TX | M0 |
| **Переходник QWIIC → USB-UART** | единственный канал отладки RX | M0, без него никак |
| USB-UART для TX | отладка TX | M0 |
| **TF-карта** | журнал трасс | M1 |
| OTG-переходник + источник 5 В | VBUS для роли host на TX | M1 |
| USB-A мама / кабель для врезки | подключение руля к TX | M1 |
| G920 + штатный БП | — | M1 |
| Xbox, ПК Windows, ПК Linux | эталоны | M2 — **есть, сняты** |

Raspberry Pi с `usb-proxy` в списке нет намеренно: M1 закрывает сниффинг
силами самого передатчика. Остаётся резервом, если USB Host на S3 окажется
слишком капризным для чистого лога.
