# Беспроводной адаптер для Logitech G920

Две платы ESP32-S3, которые вставляют радиоканал в середину USB-кабеля
G920. Одна стоит у руля и говорит с ним как USB **Host**, вторая
втыкается в консоль или ПК и **притворяется рулём**. Обратная связь идёт
через тот же канал в другую сторону, так что руль по-прежнему упирается.

Руль не вскрывается и не переделывается. Всё идёт через его штатный
кабель USB-A.

```
   Logitech G920 ──USB──▶ [ TX: ESP32-S3 ]  ))) ESP-NOW (((  [ RX: донгл ] ──USB──▶ Xbox / ПК
                            USB Host                           USB Device
```

> English version: [`README.md`](README.md)

## Состояние

**Работает.** Консоль принимает адаптер за настоящий руль, обмен
аутентификации проходит, играть по радио можно.

| Часть | Состояние |
|---|---|
| Энумерация руля, метаданные, обратная связь | готово |
| Радиотранспорт (ESP-NOW) | готово — 250 Гц без потерь, ~1.2 мс в одну сторону |
| Клонирование личности руля на донгл | готово |
| Проброс аутентификации Xbox | готово — консоль принимает руль |
| Донгл с экраном и кнопкой | написано, **на живом железе не проверено** |
| Мёртвая рука (снять силы при обрыве) | не сделано |

Замеренный бюджет задержки: собственный код — около 0.1 % пути. Остальное
это опрос USB (1–4 мс с каждой стороны) и радио (~1.2 мс). Подробности в
[`docs/LATENCY.md`](docs/LATENCY.md).

## Железо

| Роль | Плата | Почему |
|---|---|---|
| **TX** — у руля | ESP32-S3 (Supermini / DevKitC-1) | USB Host, помещается рядом с рулём |
| **RX** — у консоли | Pocket-Dongle-S3 / LilyGo T-Dongle-S3 | форм-фактор флешки, экран, втыкается прямо в консоль |

**Одна плата — одна роль.** У ESP32-S3 один USB-OTG контроллер: либо Host,
либо Device, переключение на лету невозможно. Это кремний, а не выбор
разработчика.

### Схема: TX к рулю

Штатный USB-A руля втыкается в USB-A **маму**, которая разведена на
ESP32-S3:

```
        Logitech G920                       ESP32-S3 (TX)
        штатный кабель USB-A
              │
              ▼
     ┌─────────────────┐
     │   USB-A мама    │
     │                 │
     │  1  VBUS  ──────┼──── +5 В через ключ высокой стороны ◀── GPIO21
     │  2  D−    ──────┼──────────────────────────────────────── GPIO19
     │  3  D+    ──────┼──────────────────────────────────────── GPIO20
     │  4  GND   ──────┼──────────────────────────────────────── GND
     └─────────────────┘
              │
       балласт 1 кОм с пина 1 на пин 4, прямо у розетки
```

**Ноги D+ и D− прибиты кремнием.** GPIO19 — это D−, GPIO20 — это D+.
Перенести нельзя: это сам USB-PHY, а не мультиплексор.

Цвета проводов внутри USB-кабелей (красный/белый/зелёный/чёрный) —
соглашение, а не гарантия. **Прозванивайте тестером.**

### Схема: питание

Руль питается от своего блока 24 В. Передатчик и VBUS, который он подаёт
рулю, берутся от тех же 24 В через развязанный преобразователь:

```
   БП руля 24 В ──┬──▶ сам руль
                  │
                  └──▶ URB2405YMD (24 В → 5 В) ──┬──▶ ESP32-S3, пин 5V
                                                 │
                                                 └──▶ ключ ──▶ пин 1 розетки (VBUS)

   Земля звездой: минус 5 В, GND платы и пин 4 розетки сходятся в ОДНОЙ точке.
```

Три вещи, на которых легко ошибиться:

- **VBUS подаёт передатчик, а не руль.** Самопитаемое USB-устройство не
  начнёт энумерацию, пока не увидит 5 В на VBUS — оно ждёт, что в него
  воткнули хост.
- **Не берите VBUS с пина `5V` самой платы.** На большинстве девкитов он
  висит на шине питания через диод Шоттки, и подача туда обратно кормит
  регулятор платы с его же выхода.
- **Земля USB обязана быть общей.** D+/D− меряются относительно пина 4.
  Развязанный DC-DC этого требования не отменяет: руль внутри себя
  соединяет свою USB-землю с землёй 24 В, так что развязка всё равно
  закорочена через руль. Либо принимаем общую землю, либо ставим
  настоящий USB-изолятор (ADuM4160) на линии данных — одним DC-DC по
  питанию этого не добиться.

### Ключ на VBUS

Питанием розетки распоряжается прошивка — чтобы уметь переподключать руль
самостоятельно (`-DG920_VBUS_GPIO=21`). Ключ высокой стороны из оптопары
и PNP-транзистора:

```
              +5 В ──┬──────────────────── E ┐
                     │                       │  2N3906 (PNP)
                  [10 кОм]                   │
                     ├───[1 кОм]───┐     B ──┤
                     │             │         └── C ──▶ пин 1 розетки (VBUS)
                     │      коллектор опто (4)
                     │      эмиттер опто  (3) ── GND
                     │
   GPIO21 ──[220 Ом]──▶ анод опто (1);   катод опто (2) ── GND

   Плюс балласт 1 кОм с VBUS на землю у розетки.
```

GPIO21 в единице → PNP открыт → рулю приходят честные 5 В.
GPIO21 в нуле или плата ещё грузится → руль обесточен.

Две оговорки, купленные дорого:

- **Одной оптопары мало.** Как проходной ключ она падает больше вольта
  (замерено: 3.4–3.9 В из 5 В), и руль не берёт свой порог VBUS. Её дело —
  открывать транзистор, а не нести ток.
- **Балласт обязателен.** Руль тянет с VBUS микроамперы, и без резистора,
  разряжающего узел, «выключено» не выключается: узел висит около 5 В
  десятками секунд.

### RX: донгл

Втыкается прямо в USB-порт консоли и питается от него. Паять нечего
вообще. На плате уровня T-Dongle-S3 экран показывает качество связи,
состояние руля и консоли, темп ввода и потери; единственная кнопка
переключает ступени подсветки (включая «погашено»), а удержанная три
секунды — уводит в режим прошивки.

## Сборка и заливка

[PlatformIO](https://platformio.org/), фреймворк ESP-IDF.

```bash
# передатчик (у руля)
pio run -d firmware/tx -e tx-host   -t upload    # с логами, для подъёма
pio run -d firmware/tx -e tx-prod   -t upload    # молча, для работы

# приёмник (донгл)
pio run -d firmware/rx -e rx-dongle-gip -t upload   # с логами
pio run -d firmware/rx -e rx-prod       -t upload   # молча

# юнит-тесты на хосте, железо не нужно
pio test -d firmware/native
```

Заливка донгла неудобна не по недосмотру: у него один USB-порт, и прошивка
занимает его ролью устройства. Либо **держать кнопку три секунды** — тогда
работающая прошивка сама уйдёт в загрузчик ПЗУ, либо **зажать кнопку и
воткнуть в порт**: второе делает ПЗУ, и оно работает даже когда прошивка
не запускается.

## Структура

```
firmware/tx/        передатчик — USB Host, говорит с рулём
firmware/rx/        приёмник — USB Device, говорит с консолью
firmware/common/    общий код: протокол GIP, радиолинк, личность, привязка к плате
firmware/native/    юнит-тесты, выполняются на хосте
docs/               железо, бюджет задержки, эталоны хостов, план
```

Общий код действительно общий — одна копия, которую подхватывают обе
прошивки и хостовая сборка тестов, поэтому логика протокола покрыта
тестами, которым не нужно железо.

## Что стоило больше всего времени

- **Не трогайте GPIO19/20 до подъёма стека USB.** Предстековая
  диагностика, крутившая эти ноги как обычные GPIO, оставляла PHY
  неспособным увидеть **статически подключённое** устройство: подтяжка
  руля стояла на месте, а стек вечно докладывал пустую шину. Горячее
  подключение при этом работало — поэтому «стартует, только если тронуть
  разъём» и «работает от питания с ноутбука» неделями выглядели как
  проблема с землёй. Ею они не были.
- **Два владельца одного пула номеров — всегда дефект.** Поймано трижды:
  консоль и передатчик, нумерующие сообщения рулю; труба и надёжная
  очередь на одном типе кадра; повторитель, славший отчёт с прежним
  номером GIP.
- **Печать в горячем пути управляет временем.** Хексдамп 64 байт на
  115200 занимает ~45 мс. Один раз он сорвал знакомство с рулём, другой —
  уронил цикл в watchdog. В продовых профилях лог вырезается сборкой.
