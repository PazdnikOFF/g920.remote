# Беспроводной адаптер для Logitech G920

**Это замена USB-кабеля G920 на радиоканал ESP-NOW.**

Работу делают две платы ESP32-S3. Одна стоит у руля и читает его по USB.
Вторая втыкается в консоль или ПК, и та видит её как настоящий G920.
Обратная связь идёт по тому же каналу назад, так что руль по-прежнему
упирается в руках.

Руль не надо вскрывать и переделывать — он подключается своим же кабелем.

```
   Logitech G920 ──USB──▶ [ TX: ESP32-S3 ]  ))) ESP-NOW (((  [ RX: донгл ] ──USB──▶ Xbox / ПК
                            USB Host                           USB Device
```

> English version: [`README.md`](README.md)

## Состояние

**Работает.** Консоль принимает его за настоящий руль, проверка
подлинности Xbox проходит, играть по радио можно.

| Часть | Состояние |
|---|---|
| Чтение руля: подключение, метаданные, обратная связь | готово |
| Сам радиоканал | готово — 250 обновлений/с без потерь, ~1.2 мс в одну сторону |
| Клонирование личности руля на донгл | готово |
| Проверка подлинности Xbox (пробрасывается рулю) | готово |
| Донгл с экраном и кнопкой | написано, **на живом железе не проверено** |
| Аварийное снятие сил при обрыве связи | не сделано |

Задержка: наш собственный код добавляет почти ничего — около 0.1 % от
общего времени. Почти всё остальное это опрос USB (1–4 мс с каждой
стороны) и радио (~1.2 мс). Подробности в
[`docs/LATENCY.md`](docs/LATENCY.md).

## Железо

| Роль | Плата | Почему |
|---|---|---|
| **TX** — у руля | ESP32-S3 (Supermini / DevKitC-1) | USB Host, помещается рядом с рулём |
| **RX** — у консоли | Pocket-Dongle-S3 / LilyGo T-Dongle-S3 | форм-фактор флешки, экран, втыкается прямо в консоль |

**Одна плата делает что-то одно.** У ESP32-S3 один USB-контроллер: он
может быть либо хостом, либо устройством, и переключиться на ходу не
может. Так устроен сам чип — кодом это не обойти.

### Схема: TX к рулю

Штатный USB-A руля втыкается в USB-A **маму**, которая разведена на
ESP32-S3:

```
        Logitech G920                       ESP32-S3 (TX)
        штатный кабель USB-A
              │
              ▼
     ┌─────────────────┐
     │   USB-A мама    │
     │                 │
     │  1  VBUS  ──────┼──── +5 В через ключ высокой стороны ◀── GPIO21
     │  2  D−    ──────┼──────────────────────────────────────── GPIO19
     │  3  D+    ──────┼──────────────────────────────────────── GPIO20
     │  4  GND   ──────┼──────────────────────────────────────── GND
     └─────────────────┘
              │
       балласт 1 кОм с пина 1 на пин 4, прямо у розетки
```

**Ноги D+ и D− поменять нельзя.** GPIO19 — это D−, GPIO20 — это D+. Они
идут прямо в USB-блок чипа, поэтому на других пинах ничего не заработает.

Цвета проводов внутри USB-кабелей (красный/белый/зелёный/чёрный) — только
соглашение, а не гарантия. **Проверяйте мультиметром.**

### Схема: питание

Руль питается от своего блока 24 В. Передатчик и VBUS, который он подаёт
рулю, берутся от тех же 24 В через развязанный преобразователь:

```
   БП руля 24 В ──┬──▶ сам руль
                  │
                  └──▶ URB2405YMD (24 В → 5 В) ──┬──▶ ESP32-S3, пин 5V
                                                 │
                                                 └──▶ ключ ──▶ пин 1 розетки (VBUS)

   Земля звездой: минус 5 В, GND платы и пин 4 розетки сходятся в ОДНОЙ точке.
```

Три вещи, на которых легко ошибиться:

- **5 В на VBUS даёт адаптер, а не руль.** Устройство со своим питанием
  молчит, пока не увидит 5 В на VBUS: так оно понимает, что его во
  что-то воткнули.
- **Не берите эти 5 В с пина `5V` самой платы.** На большинстве плат он
  стоит за диодом, и питание, поданное туда снаружи, идёт в регулятор
  платы с обратной стороны.
- **У обеих сторон должна быть общая земля.** D+ и D− меряются
  относительно пина 4, значит рулю и плате нужна одна точка отсчёта.
  Развязанный DC-DC этого не меняет: внутри руля USB-земля и так соединена
  с землёй 24 В, поэтому развязка обходится через сам руль. Либо
  соглашаемся на общую землю, либо ставим настоящий USB-изолятор
  (ADuM4160) на линии данных — развязкой по питанию этого не добиться.

### Ключ на VBUS

Эти 5 В включает сама прошивка, чтобы уметь переподключить руль без
человека (`-DG920_VBUS_GPIO=21`). Ключ — оптопара, открывающая
PNP-транзистор:

```
              +5 В ──┬──────────────────── E ┐
                     │                       │  2N3906 (PNP)
                  [10 кОм]                   │
                     ├───[1 кОм]───┐     B ──┤
                     │             │         └── C ──▶ пин 1 розетки (VBUS)
                     │      коллектор опто (4)
                     │      эмиттер опто  (3) ── GND
                     │
   GPIO21 ──[220 Ом]──▶ анод опто (1);   катод опто (2) ── GND

   Плюс балласт 1 кОм с VBUS на землю у розетки.
```

GPIO21 в единице → PNP открыт → рулю приходят честные 5 В.
GPIO21 в нуле или плата ещё грузится → руль обесточен.

Две вещи, которые дались дорого:

- **Одной оптопары мало.** Если ток идёт через неё саму, она теряет больше
  вольта (замерено: 3.4–3.9 В вместо 5 В), и рулю не хватает напряжения,
  чтобы проснуться. Её дело — открывать транзистор, а не нести нагрузку.
- **Резистор 1 кОм не пропускать.** Руль тянет с VBUS микроамперы, и если
  линию нечем разрядить, «выключено» ничего не выключает: напряжение
  остаётся около 5 В ещё десятки секунд.

### RX: донгл

Втыкается прямо в USB-порт консоли и питается от него. Паять нечего
вообще. На плате уровня T-Dongle-S3 экран показывает качество связи,
состояние руля и консоли, темп ввода и потери; единственная кнопка
переключает ступени подсветки (включая «погашено»), а удержанная три
секунды — уводит в режим прошивки.

## Сборка и заливка

[PlatformIO](https://platformio.org/), фреймворк ESP-IDF.

```bash
# передатчик (у руля)
pio run -d firmware/tx -e tx-host   -t upload    # с логами, для подъёма
pio run -d firmware/tx -e tx-prod   -t upload    # молча, для работы

# приёмник (донгл)
pio run -d firmware/rx -e rx-dongle-gip -t upload   # с логами
pio run -d firmware/rx -e rx-prod       -t upload   # молча

# юнит-тесты на хосте, железо не нужно
pio test -d firmware/native
```

Заливка донгла требует лишнего шага, и обойти это нельзя: у платы один
USB-порт, и прошивка занимает его, изображая руль. Либо **держать кнопку
три секунды** — тогда работающая прошивка сама уйдёт в загрузчик, либо
**зажать кнопку и воткнуть в порт**: это делает ПЗУ чипа, и работает даже
когда прошивка вообще не запускается.

## Структура

```
firmware/tx/        передатчик — USB Host, говорит с рулём
firmware/rx/        приёмник — USB Device, говорит с консолью
firmware/common/    общий код: протокол GIP, радиолинк, личность, привязка к плате
firmware/native/    юнит-тесты, выполняются на хосте
docs/               железо, бюджет задержки, эталоны хостов, план
```

Общий код действительно общий — одна копия, которую подхватывают обе
прошивки и хостовая сборка тестов, поэтому логика протокола покрыта
тестами, которым не нужно железо.

## Ошибки, которые стоили больше всего времени

- **Не трогайте GPIO19/20 до подъёма стека USB.** У нас был
  диагностический код, который дёргал эти ноги как обычные GPIO при
  загрузке. После него USB-блок чипа переставал видеть устройство,
  которое **уже подключено**: руль стоял на месте и держал свою линию
  поднятой, а стек всё равно вечно докладывал пустую шину. Воткнуть руль
  позже при этом работало — поэтому «стартует, только если тронуть
  разъём» и «работает от питания с ноутбука» неделями выглядели как
  проблема с землёй. Ею они не были.
- **Нельзя, чтобы две части кода нумеровали сообщения из одного пула.**
  Из-за этого получилось три разных дефекта: консоль и передатчик, оба
  нумерующие сообщения рулю; труба и очередь повторов на одном типе
  кадра; повторитель, славший отчёт со старым номером.
- **Печать внутри кода, критичного ко времени, меняет это время.**
  Напечатать 64 байта в шестнадцатеричном виде через порт на 115200
  занимает около 45 мс. Одного этого хватило, чтобы сорвать знакомство с
  рулём, а в другой раз — уронить цикл в watchdog. В рабочих сборках лог
  вырезается целиком.
